# v1.0.0 implementation plan (archived)

Completed in [v1.0.0](https://github.com/CHNISam/Genshin-Theater-Copilot/releases/tag/v1.0.0).
This is historical design/validation context, not an active task list. Current
project execution status is maintained only in [Backlog.md](../Backlog.md);
gameplay execution follows [SOP.md](SOP.md).

User scope: preserve the existing strategic search; add current-fight evidence and a mechanical stop gate; absorb history; ship a small Windows portable release.

1. RED/GREEN: current fight contract + non-convergence regressions. Keep strategic search APIs. Two flat failures stop; meaningful progress is measured against best comparable observation; failed mechanisms, missing metrics and total trial budgets cannot masquerade as convergence. Reroute requires fresh reviewed evidence, a substantive changed strategy and a measurable hypothesis, preserving history across plan names.
2. RED/GREEN: JSON validation, one CLI and atomic state writes. Check at the actual trial authorization entry; separate authorization from result logging. Refuse unavailable teams, stale snapshots, overspending and unknown decision-relevant season facts. Keep future alternative routes and recruitment conditionality.
3. Integrate all eight sources into a source index, scoped retrospective cases and regression fixtures. Separate observed outcome, untested proposal and unknown. Replace obsolete SOP text with one canonical flow and a concise Chinese quick start. Provide season validation/update prompt and optional creator watchlist.
4. Build ZIP using pinned official CPython embeddable distribution and SHA-256. Native Windows CI extracts to a clean Chinese/spaced directory and exercises its bundled entry/runtime, fail→stop→reroute→pass, self-test and invalid state. Release only after validation.
5. Fresh whole-branch review; resolve meaningful findings with RED/GREEN. Commit using expected parent, observe CI, verify release download and archive checksums. No success claim without actual results.

Review focus: cosmetic plan edits; stale evidence; changed objective/window; poor-data attempts; budget exhaustion; attempt logging outside authorization; rollback/overwrite; stale run contract; conditional ≠ proof of clear; Windows PATH/cwd/Unicode; release gating; provenance and historical hallucinations.
